# Design: add-internet-speed-ping

## Context

Проект `/Users/altair/sandbox/ping` содержит задание в `README.md` (скрипт-замерятель скорости интернета). Скрипт `ping.py` будет добавлен как единственный исполняемый модуль в корне проекта. В проекте уже есть `.venv/`, но без `httpx`. Python 3.14.2 (PEP 668 — установка только в venv).

Мотивация — в `proposal.md` (см. Why).

## Goals / Non-Goals

**Goals:**
- Один файл `ping.py` с читаемой структурой сверху вниз: импорты → константы → dataclass-модели → измерение → отчёт → main.
- Все измеримые требования из `specs/cli-ping/spec.md` выполнены.
- Тесты на чистую логику агрегации (без моков сети) проходят.
- README проекта содержит пример запуска.

**Non-Goals:**
- Слойная архитектура, DI, фабрики, репозитории — это отдельный change.
- Retry с exponential backoff — задание не требует, маскирует реальные сбои.
- Прогрев первого запроса — усложняет интерпретацию отчёта.
- HTTP/2 — мультиплексинг искажает семантику «последовательных» запросов.
- Логирование через модуль `logging` — для CLI достаточно `print` с префиксом.
- Конфиг-файлы, переменные окружения — overkill для задачи.

## Decisions

### D1. HTTP-клиент: `httpx.AsyncClient` с `http2=False`

**Решение:** использовать `httpx` (а не `aiohttp` или `requests`).

**Почему:**
- `httpx` имеет нативный async API, что позволяет естественно перейти к параллельным замерам в будущем (отдельный change).
- `requests` синхронный — работает, но лишает задела на расширение.
- `aiohttp` — ещё один клиент, плюс свой event loop; `httpx` — стандартный async-клиент с простым API.

**Альтернативы:**
- `urllib.request` (stdlib) — нет async, нет удобного API.
- `requests` — нет async, синхронный код в `asyncio.run()` блокирует event loop.

### D2. Замер времени: `time.perf_counter()` от старта запроса до `response.aread()`

**Решение:** `time.perf_counter()` (монотонные часы высокого разрешения) для каждого запроса; замер оборачивает `await client.get(url)` с `stream=True` и явным `await response.aread()`.

**Почему:**
- `time.perf_counter()` — монотонные, не подвержены скачкам системного времени (в отличие от `time.time()`).
- `response.aread()` гарантирует, что тело прочитано полностью до того, как мы зафиксируем время окончания.
- Без `stream=True` + `aread()` httpx может вернуть объект Response до того, как тело полностью скачано (lazy body), и замер покажет фантомно быстрый результат.

**Альтернативы:**
- Замер «до первого байта» (TTFB) — другая метрика, не то что просит задание.
- Чтение чанками вручную — даёт тот же результат, но больше кода без выигрыша.

### D3. Замер байт: длина response body, не Content-Length

**Решение:** считать `len(response.content)` после `aread()`, не доверять заголовку `Content-Length`.

**Почему:**
- Сервер может прислать `Content-Length: 1000000`, но разорвать соединение после 500 КБ — тогда честный замер должен использовать реально полученные байты.
- `Content-Length` иногда отсутствует (chunked transfer encoding).

### D4. Модели: `dataclass(frozen=True, slots=True)`

**Решение:**
- `SingleRequestResult` — `@dataclass(frozen=True, slots=True)`.
- `SpeedReport` — `@dataclass(frozen=True)`, без `slots` (содержит список, slots для списков не дают ощутимого выигрыша).

**Почему:**
- `frozen=True` — результат замера нельзя случайно мутировать после создания; полезно при тестах и для дисциплины.
- `slots=True` на `SingleRequestResult` — экономит память, запрещает добавлять поля «по ходу» (явная модель).
- Не используем `pydantic.BaseModel` — здесь нет нужды в валидации runtime-данных, только структура.

### D5. Валидация URL: собственный валидатор на `urllib.parse.urlparse`

**Решение:** функция `validate_url(url: str) -> str`, которая:
1. Парсит через `urlparse`.
2. Требует `scheme in {"http", "https"}`.
3. Требует непустой `netloc`.
4. Возвращает нормализованный URL или бросает `ValueError` с понятным сообщением.

**Почему:**
- `pydantic.HttpUrl` доступен в экосистеме Python, но тащить pydantic ради одного валидатора — overkill.
- `argparse(type=...)` принимает callable, который может бросить `ArgumentTypeError` — стандартный путь.

**Альтернативы:**
- `pydantic.HttpUrl` — работает, но лишняя зависимость для CLI.
- Регулярка — хрупко, не покрывает edge-кейсы.

### D6. Структура отчёта: aggregate + per-request

**Решение:** два уровня метрик:
- **Aggregate** = `total_bytes / total_time_s` — главная цифра «скорость канала», как у Speedtest.net.
- **Per-request min/max/mean** — диагностика (показывает, был ли один запрос аномально медленным).

**Почему:** задание просит «среднее время», но реальная скорость интернета = сколько байт прокачалось за сколько секунд через канал. Оба уровня в одном отчёте — это «честный» замер без потери информации.

### D7. Формат вывода: `print_report()` + `to_json()`, выбор через `--json`

**Решение:** две отдельные функции форматирования, `main()` вызывает одну из них в зависимости от флага.

**Почему:**
- Разделение форматирования и измерения — тестируемо.
- `--json` стандартен для CLI-утилит (jq-парсится).

### D8. Exit codes: 0 / 1 / 2

**Решение:** `sys.exit(0|1|2)`.

**Почему:**
- 0 = успех, 1 = runtime-сбой (часть запросов упала), 2 = usage error (невалидный вход).
- Это конвенция Unix; CI/обёртки могут различать «плохой канал» от «опечатка в URL».

## Risks / Trade-offs

- **[Нет retry]** → одна сеть-флуктуация может дать `failed=1/10`. **Mitigation:** `failed=1` явно в отчёте, пользователь сам решит перезапустить.
- **`time.perf_counter` включает DNS-resolve в первый раз** → первый запрос будет чуть медленнее. **Mitigation:** не маскируем, оставляем в статистике с пометкой в human-readable выводе, что «первый запрос может включать DNS+TCP+TLS handshake».
- **`httpx.AsyncClient` создаётся один раз на все 10 запросов** → connection reuse ускоряет замер (не нужно переустанавливать TCP/TLS). Это плюс к честности замера.
- **HTTP/2 отключён** → если сервер поддерживает только HTTP/2, скрипт всё равно работает (httpx переключается на HTTP/1.1). Trade-off в сторону семантики, не максимальной скорости.
- **`--timeout 10` может быть мало для медленного канала** → замер покажет `failed=N/10` без штрафа exit code 1. **Mitigation:** пользователь сам поднимает `--timeout`.

## Migration Plan

Это новый код, миграция не требуется. После реализации:

1. `pip install httpx` в `.venv`.
2. `python ping.py --url <test>` — smoke test.
3. `pytest tests/` — тесты зелёные.
4. Merge в `develop` через PR.
